# データベース設計

DB は Supabase（PostgreSQL）を使う。テーブルの定義は `supabase/migrations/` の SQL が正で、このファイルはその説明。

## 反映方法

Supabase ダッシュボードの **SQL Editor** で、`supabase/migrations/` の SQL をファイル名の順に実行する。

1. `20261120000000_create_tags.sql` … tags テーブルと RLS の作成
2. `20261120000100_insert_system_tags.sql` … システムタグの初期データ
3. `20261120000200_create_tag_compat.sql` … 相性表 tag_compat の作成と初期データ

実行したら `backend/.env` に `SUPABASE_URL` と `SUPABASE_PUBLISHABLE_KEY` を設定する（`backend/.env.example` 参照）。

## タグと相性表のしくみ

1. **準備（最初に1回）**：タグの一覧を `tags` に登録し、「場面タグ × 服タグ」の相性点 α を `tag_compat` に入れる。
2. **日々の操作**：服にタグを付ける（`clothes_tags`）、予定に場面タグを付ける（`event_tags`）、好みのテイストを選ぶ（`user_style_tags`）。
3. **提案するとき**：予定の場面タグと各服のタグを相性表で突き合わせ、α を足す。禁止の組み合わせに当たる服は除外する。残った服でコーデを組み、色・天気・好みの点も足して高い順に並べる。
4. **運用**：「良かった/微妙」を `feedback` に記録し、あとから α の調整に使う。

新しい場面や服の種類が増えたら、`tags` と `tag_compat` に行を足すだけで対応する。

> 2 と 4 のテーブル（`clothes_tags`、`event_tags`、`user_style_tags`、`feedback`）は、服・予定・ユーザーのテーブルができてから作る。

## テーブル

### tags（タグ）

システムタグとユーザー独自タグを同じテーブルで管理する。

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| id | bigint | ○ | 主キー（自動採番） |
| type | text | ○ | タグの種類。`scene`（場面）/ `item`（服）/ `style`（テイスト） |
| name | text | ○ | 表示名（1〜30文字） |
| user_id | uuid |  | `NULL` ならシステムタグ。値があればそのユーザーの独自タグ（`auth.users.id`） |
| sort_order | integer | ○ | 表示順（小さい順）。初期値 0 |
| created_at | timestamptz | ○ | 作成日時 |

- 同じ種類の中で名前は重複できない（システムタグ同士、同じユーザーのタグ同士）。
- ユーザーを削除すると、そのユーザーの独自タグも削除される。

#### アクセス制御（RLS）

| 操作 | できる人 |
| --- | --- |
| 読み取り | システムタグは誰でも。独自タグは本人だけ |
| 追加・更新・削除 | 独自タグを本人だけ。システムタグはアプリから変更できず、SQL で管理する |

#### システムタグの初期データ

| 種類 | タグ |
| --- | --- |
| 場面 | 通学、バイト、面接、休日お出かけ、運動 |
| 服 | スーツ、ジャケット、シャツ、Tシャツ、パーカー、スラックス、デニム、ジャージ、スニーカー、革靴 |
| テイスト | シンプル、きれいめ、カジュアル、モノトーン、ストリート |

### tag_compat（相性表）

「場面タグ × 服タグ」ごとの相性点。表にない組み合わせは 0 点として扱う。

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| scene_tag_id | bigint | ○ | 場面タグ（`tags.id`） |
| scene_tag_type | text | ○ | 常に `scene`。場面タグ以外を入れられないようにするための列 |
| item_tag_id | bigint | ○ | 服タグ（`tags.id`） |
| item_tag_type | text | ○ | 常に `item`。服タグ以外を入れられないようにするための列 |
| score | integer | ○ | 相性点 α（-5〜+5） |
| is_forbidden | boolean | ○ | `true` ならこの場面ではその服を候補から除外する |
| updated_at | timestamptz | ○ | 更新日時 |

- 主キーは `(scene_tag_id, item_tag_id)`。同じ組み合わせは1行だけ。
- タグを削除すると、そのタグを使った行も削除される。
- RLS：誰でも読める。変更はアプリからはできず、SQL で管理する。

| 場面 | プラス | マイナス | 禁止 |
| --- | --- | --- | --- |
| 通学 | Tシャツ・パーカー・デニム・スニーカー +2、シャツ +1 | スーツ -3 | |
| バイト | スニーカー +2、シャツ・スラックス +1 | | |
| 面接 | スーツ +5、ジャケット・シャツ・スラックス・革靴 +3 | Tシャツ・スニーカー -3 | デニム・パーカー・ジャージ（-5） |
